    Multi-Sample Anti-Aliasing (MSAA)

    Multi-Sample Anti-Aliasing (MSAA) is a hardware-accelerated technique used in real-time rendering to reduce the visual artifact known as aliasing — the "jagged edges" or "staircase" effect that appears on diagonal and curved geometry.

    Overview

    When a triangle is rasterized, the GPU must decide which pixels it covers. Without anti-aliasing, a pixel is either fully inside or fully outside the triangle — a binary decision that produces hard, jagged boundaries. MSAA solves this by sampling each pixel multiple times at sub-pixel locations and averaging the results to produce a smoother edge.

    !!! info "Key Distinction" MSAA only runs the fragment shader once per pixel, but performs the depth and stencil test at every sub-sample. This makes it significantly cheaper than Super-Sample Anti-Aliasing (SSAA), which shades at every sample.

    How It Works

    1. Sub-Sample Generation

    For each pixel, the GPU generates N sample points arranged within the pixel's bounds (where N is the MSAA level, e.g. 2×, 4×, 8×). The exact positions follow a vendor-defined pattern designed to maximize coverage variety.

    ┌─────────────────┐
│  · ─ ─ ─ ─ · │   4× MSAA sample positions
│  │    ·        │   within a single pixel
│       │    ·  │
│  · ─ ─ ─ ─ · │
└─────────────────┘

    2. Coverage and Depth Testing

    The GPU evaluates each sub-sample against the triangle's coverage and the depth buffer independently. A sub-sample is "covered" if it falls inside the triangle's projected area.

    3. Fragment Shading

    The fragment shader runs once per pixel (not once per sample), using the centre of the pixel (or a centroid-interpolated position) to compute the colour output.

    4. Resolve

    At the end of the frame, the multisample buffer is resolved: the N sample colours for each pixel are averaged into a single value, which is written to the final framebuffer.

    MSAA Levels

    Level Samples per Pixel Performance Cost Edge Quality
    2× 2 Low Moderate
    4× 4 Medium Good
    8× 8 High Very Good
    16× 16 Very High Excellent

    !!! tip 4× MSAA is the most common choice in games and real-time applications, balancing image quality with GPU memory and bandwidth cost.

    Memory and Bandwidth Impact

    MSAA stores N depth, stencil, and colour samples per pixel in a multisample render target. This multiplies the render target's memory footprint by N:

    • A 1920×1080 RGBA8 framebuffer at 4× MSAA uses approximately 32 MB instead of 8 MB.
    • Bandwidth during the resolve pass increases proportionally.

    !!! warning "Deferred Rendering Incompatibility" MSAA does not compose cleanly with deferred shading pipelines. The G-buffer stores per-pixel surface data, meaning MSAA sub-samples cannot be resolved before lighting is applied. Alternatives such as FXAA, TAA, or per-sample shading must be used instead.

    Usage

    === "OpenGL"

    ```c
// Request a multisample framebuffer from your windowing library (e.g. GLFW)
glfwWindowHint(GLFW_SAMPLES, 4);

// Enable multisampling
glEnable(GL_MULTISAMPLE);
```

    === "Vulkan"

    ```c
VkPipelineMultisampleStateCreateInfo multisampleState = {
    .sType                = VK_STRUCTURE_TYPE_PIPELINE_MULTISAMPLE_STATE_CREATE_INFO,
    .rasterizationSamples = VK_SAMPLE_COUNT_4_BIT,
    .sampleShadingEnable  = VK_FALSE,
};
```

    === "Direct3D 11"

    ```cpp
DXGI_SWAP_CHAIN_DESC scDesc = {};
scDesc.SampleDesc.Count   = 4;   // 4× MSAA
scDesc.SampleDesc.Quality = 0;
```

    === "WebGPU"

    ```ts
const texture = device.createTexture({
  size: [canvas.width, canvas.height],
  sampleCount: 4,
  format: "bgra8unorm",
  usage: GPUTextureUsage.RENDER_ATTACHMENT,
});
```

    Per-Sample Shading

    By default, the fragment shader runs once per pixel. You can opt into running it once per sample for higher quality, at a cost equal to SSAA:

    === "GLSL"

    ```glsl
// Force per-sample evaluation
in vec2 texCoord; // becomes per-sample when qualifier is used

layout(location = 0) out vec4 fragColor;

void main() {
    fragColor = texture(uTexture, texCoord);
}
```

    === "Vulkan"

    ```c
multisampleState.sampleShadingEnable  = VK_TRUE;
multisampleState.minSampleShading     = 1.0f; // shade at every sample
```

    !!! note Per-sample shading is rarely needed in practice and defeats the primary performance advantage of MSAA.

    Centroid Interpolation

    When a pixel is only partially covered by a triangle, interpolated varyings evaluated at the pixel centre may lie outside the triangle, producing artefacts. Centroid interpolation moves the evaluation point to the centroid of the covered samples, keeping it inside the triangle.

    === "GLSL"

    ```glsl
centroid in vec2 texCoord;
```

    === "HLSL"

    ```hlsl
centroid float2 texCoord : TEXCOORD0;
```

    Alternatives

    Technique Type Works with Deferred? Notes
    SSAA Spatial Yes Highest quality, highest cost
    MSAA Spatial Poorly Best quality-to-cost for forward rendering
    FXAA Post-process Yes Fast, blurs fine detail
    SMAA Post-process Yes Better edge detection than FXAA
    TAA Temporal Yes Industry standard; requires motion vectors
    DLAA AI-based Yes High quality, vendor-specific

    Summary

    • MSAA reduces geometric aliasing by testing coverage at multiple sub-pixel locations while keeping a single shading pass per pixel.
    • It is well-suited to forward rendering pipelines and natively supported by all major graphics APIs.
    • Choose your sample count based on your performance budget — 4× is the practical sweet spot for most applications.
    • For deferred pipelines or post-process stacks, consider TAA or SMAA instead.
