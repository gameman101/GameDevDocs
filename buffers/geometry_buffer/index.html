    Geometry Buffer (G-Buffer)

    The G-Buffer is a collection of textures used in Deferred Rendering to store geometric information about a scene. Instead of calculating lighting immediately for every triangle, the renderer "defers" the lighting until a second pass, using the data stored in these buffers.

    Why use a G-Buffer?

    In traditional "Forward Rendering," if two triangles overlap, the GPU might calculate the lighting for the triangle in the back, only to have the front triangle draw over it later. This is called Overdraw and it wastes performance.

    The G-Buffer solves this by rendering the scene's properties once, then calculating lighting only for the pixels that are actually visible to the camera.

    Standard G-Buffer Components

    A typical G-Buffer consists of several screen-sized textures, each storing a different piece of information:

    1. Diffuse / Albedo Buffer

    Stores the "base color" of the objects without any lighting or shadows applied. It is essentially what the world would look like under perfectly flat, ambient light.

    2. Normal Buffer

    Stores the world-space or view-space Surface Normals ($x, y, z$ directions). This tells the lighting engine which way each pixel is facing so it can calculate how light should bounce off it.

    3. Depth Buffer (Z-Buffer)

    Stores the distance from the camera to the object. This is critical for positioning light sources in 3D space relative to the surfaces and for generating shadows.

    4. Specular / Roughness Buffer

    Stores material properties, such as how "shiny" or "rough" a surface is. In a PBR (Physically Based Rendering) workflow, this might also include a "Metallic" map.

    The Two-Pass Process

    Pass 1: Geometry Pass

    The scene is rendered, and instead of a final image, the GPU outputs data into the textures mentioned above. At the end of this pass, no lighting has been calculated yet.

    Pass 2: Lighting Pass

    The GPU looks at every pixel in the G-Buffer. It takes the Normal, the Depth, and the Color, then calculates the final lighting for that single pixel.

    !!! success "The Advantage" Because lighting is calculated in "screen space" during the second pass, the complexity of the scene depends on the resolution of the screen, not the number of triangles in the scene. This allows for hundreds of dynamic lights in a single frame.

    Limitations

    Weakness Description
    Memory Bandwidth Writing to 4-5 textures at once is very heavy on GPU memory.
    Transparency G-Buffers struggle with glass or water because they can only store data for one "layer" of depth per pixel.
    Anti-Aliasing Traditional MSAA (Multi-Sample Anti-Aliasing) is difficult to implement with a G-Buffer; most games use TAA or FXAA instead.
